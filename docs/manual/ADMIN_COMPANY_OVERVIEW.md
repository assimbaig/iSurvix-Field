# Company overview and update notices

Company Admins start on **Dashboard → Company overview**. The page shows records within their existing company, industry and project permissions. Selecting a project narrows the overview; searching the project table filters that table.

## Read the summary

| Total | Meaning |
|---|---|
| Sites | Distinct saved site IDs within each permitted project. A site can have several activities. |
| Photos | Unique saved photo evidence IDs. Linking one photo to several checklist points does not increase this total. |
| Activities | Saved checklist tasks and assignments that do not yet have a checklist. A linked assignment and checklist count once. |
| Projects | Projects within the selected permitted scope. |
| Clients | Client organizations in the Admin's company and assigned industry. A selected project shows its linked client. |
| People | Distinct active project members in the selected scope. Multiple project grants do not inflate the total. |

**Projects at a glance** shows site, activity and photo totals for each project. Use its search, page controls and internal scrollbar for larger lists.

**Waiting for review** shows recorded QA, Team Lead and Client stages. Historical records whose stage cannot be verified cheaply appear separately as **Other / historical**. These counters do not approve work or give the Admin an engineering-review permission. Open the existing task workspace for its full workflow and review record.

## Create records

- **New project:** complete the existing project form. Company and industry come from the Admin account; existing review-route and template requirements still apply.
- **New task:** open the existing task-entry page, choose a permitted project, then use single-site entry or bulk site import.
- **New client:** create a client organization within the existing company and industry. This does not create a client's login account.
- **Invite user:** choose the permitted role and project. The invitation must be accepted before it becomes an active account. Follow the displayed delivery status; a created invitation does not prove an email was delivered. A private manual invitation link remains available where supported.

Validation errors keep entered values and reopen the relevant form. A save is successful only after the server confirms it. Existing role, project and approval restrictions remain in force.

## What's new after an update

An authenticated user sees the current release's update notice when entering the application after that version is installed. It applies to all active application roles.

- **Don't show this update again** is checked initially. **Continue** saves that choice for the signed-in account and this release, including later logins and other devices.
- Uncheck it, close the notice, press Escape or choose **Continue for this login** to dismiss it for the current login only.
- A future installed release has a different identity and shows a new notice. Remembering one update does not disable future update notices.
- If saving cannot be confirmed, use Retry or continue for the current login. The interface does not claim a permanent choice was saved until the server confirms it.

The notice changes no survey answer, evidence link, engineering decision or approval.
